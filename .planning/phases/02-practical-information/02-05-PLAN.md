<assumption_delta_decision>
**Signal:** `pluralization` on the term `fallback`, fired by the ROADMAP line "CONTEXT.md D-12
promotes the written directions from a fallback to always visible above the video".

**The noun that is now primary:** *the always visible practical guidance*, not *the conditional
fallback*.

**Decision: `promote`.** The map's "the address above already works" guidance currently exists only
inside `.map-wait`, a layer whose visibility is conditional on a state (`blocked`) the page cannot
reliably compute, because a same origin page cannot inspect a cross origin frame's contents. This
plan promotes that guidance to an unconditional element and demotes the state driven waiting line to
what it honestly is: status about the *load*, not the guest's only route to the guidance.

This is the same move D-12 already made once in this phase, for the same reason: a fallback that
appears only when a failure is detectable is not a fallback on the network where the failure is
undetectable. Adding the new element *alongside* a still conditional guidance path was rejected,
because it would leave the fast failure network exactly where the verification found it.

**Invariant this generalisation implies** (suggested, not required): on every render path where the
map slot exists, the guidance element exists too. Task 1's acceptance criteria assert both halves of
it (created beside the slot, removed with the slot).
</assumption_delta_decision>
