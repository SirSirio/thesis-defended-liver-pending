## Stated planner decisions

1. **Key naming follows 02-UI-SPEC.md, not 02-PATTERNS.md.** PATTERNS Q3 suggests
   `loc.notes.entrance`; the approved UI contract specifies `notes.entrance` and
   `access.notes.heading`. The approved contract wins. Recorded so the divergence reads as a
   decision rather than an oversight.
2. **`#location-body` is split into two owned children.** `renderLocation()` re-runs on every
   language switch, so a single rebuilt container would destroy a mounted map frame and force
   a second network fetch to Google. Establishing `#loc-data` and `#loc-map` now is what lets
   plan 02 add the map without an architectural change.
3. **No `tdd="true"` and no unit tests.** The project has no package manager, no test runner
   and a hard no-build-step constraint, so automated verification here is Node syntax and
   contract assertions plus source gates, and browser behaviour goes to `human-check`.
4. **The one-way rating on task 1 carries no checkpoint, deliberately.** Publishing a private
   residence address on a public page cannot be undone, so the rating is honest. A
   `checkpoint:decision` is still omitted because CONTEXT.md D-01 records the owner confirming
   this exact address and the flagged consideration records the tradeoff as accepted on
   purpose. Gating a decision the human already made is re-asking, not confirming, and the
   reversibility reference names that as an anti-pattern. `verify plan-structure` warns about
   the missing checkpoint; that warning is expected here and this line is the answer to it.
