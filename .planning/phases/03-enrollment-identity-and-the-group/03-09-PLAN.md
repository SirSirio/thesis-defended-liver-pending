<objective>
Close gap 3 of `03-VERIFICATION.md`, and the two nudge-region warnings that share its shape.

`daysUntil()` is `Math.ceil((ms - Date.now()) / 86400000)`. For any deadline between zero and
twenty-four hours in the past that expression is `-0`, and `-0 === 0` is true in JavaScript, so
the ladder takes the `days === 0` branch and the bar renders "Registration closes today." for a
full day **after** registration closed. `renderDeadline()` uses `Date.now() > deadlineMs` and has
already hidden the hero line by then, so on one screen the hero says nothing and the bar says
there is still time. The configured deadline is 2026-09-26, so this fires on 2026-09-27. It is
dated, not hypothetical.

The corollary is worse than the bug. `nudge.enrol.today` is unreachable in its intended meaning:
no positive offset produces zero, so the string only ever renders after the deadline has passed.
And the gate that should have caught it, Table G's `exactly 0` row, was exercised with a deadline
of minus one hour and recorded Pass, because the ladder does render that key there. The row's
intent is the last day *before* closing. That is a seventh instance of the pattern this phase
recorded six times, and it is the one the 43-case mutation sweep could not catch, because
mutating the source correctly reddens a gate that is asserting the wrong thing.

Two warnings in the same region round it out. `forgetIdentity()` resets three of four session
flags, so from the withdrawn panel the panel rebuilds under the control the guest just pressed and
focus falls to `<body>` (WR-06). And `hideNudge()` does not cancel `showNudge()`'s queued frame,
so registering again slides the bar in over the soft keyboard and then snaps it away with no
transition (WR-07).

Purpose: this is the smallest gap and the largest lesson. It is dated six weeks out, so it is
last by risk; it is the phase's seventh broken gate, so its fix is worth more than the bug it
closes.

Output: `app.js` with one close test and one day function shared by both surfaces, a ladder whose
every branch is reachable in its intended meaning, the two nudge-region warnings closed, a
re-anchored Table G, and a written disposition for every remaining review finding.

## The decision this plan makes, and why it is not the smaller one

`03-VERIFICATION.md` offers two ways to close the corollary: **delete `nudge.enrol.today` from all
three tables**, or **re-derive it from the calendar date**. This plan re-derives.

Deleting is smaller and it is wrong. With the close test added and the millisecond ladder kept,
the actual last day renders `nudge.enrol.last`, "Registration closes tomorrow", because at 09:00
on the deadline's own date there are fifteen hours left and `Math.ceil` of that is 1. That is a
second false statement, printed on the day the pressure is supposed to peak. The string
`nudge.enrol.today` makes a calendar claim, not a twenty-four-hour-window claim, and the honest
fix is to make the code make the same claim the string does. Re-deriving also leaves all 156 keys
in place, so the trilingual parity contract is untouched and no key has to be removed from three
tables at once.

## How every gate in this plan is run

Same method as plan 03-08, and the same reason. The shipped function is sliced out of `app.js` by
brace matching and run in a fresh Node process with stubs standing in only for the browser objects
it closes over, so **no branch condition is ever re-typed** and a change to `app.js` changes the
gate result. Gates run as `node -e` from the repository root and add no file to the repository.

One improvement on plan 03-06's method, which is worth stating because 03-06's Table G rows were
produced by moving `enrollment.deadline` on disk five times and writing it back: the harness here
declares `deadlineMs` in the evaluated scope and hands it to the sliced functions directly. No
config file is mutated, so there is no restoration to assert and no window in which a committed
value is wrong.

Every gate states the intent it asserts and why the shipped implementation cannot satisfy it.
