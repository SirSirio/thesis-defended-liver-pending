# Plan 04.1-01 summary: the upload control stops being a form

Shipped whole. No Supabase change, no video, no schema. Plan 2 is untouched.

## The finding that reframed the work

The owner said the upload block was "quite squared". That turned out to be measurable
rather than a matter of taste.

`:root[data-awake="1"]` transitions `--r-sm` 2 to 10px, `--r-md` 8 to 18px, `--r-lg` 10 to
28px and `--glass` and `--lift` 0 to 1, over 1.0 to 1.4 seconds. The institutional mask is
square and it softens, and that is the page's central visual joke.

**The uploader was the one block that sat out that transition.** Measured on the live page
at 390px with `data-awake` set:

| Element | Before |
|---|---|
| `.uploader` | 0px, transparent, no border, no padding. Not a card at all. |
| `.uploader__acts .btn` | 10px, the smallest value in the system |
| `.queue` | 0px |
| `.uploader__status` | 0px |
| `.mine__tile`, for contrast | **18px**, like the rest of the page |

So the fix was not a new rounded style invented beside the existing one. It was this block
finally speaking the language the page already speaks, which is also the only version that
leaves the DTU parody standing.

After: card, button and zone all compute **8px institutional and 18px awake**, and the
shadow rides `--lift`. The block transitions with the page.

## What changed, in order

1. **The card.** `.uploader` gains `--surface`, a `--rule` border, `--r-md` and `--s-5`
   padding, plus the `--lift` shadow expression copied verbatim from `.album__tile` so there
   is one lift value on the page. `--r-lg` was rejected: 28px on a full width card at 390px
   reads as a consumer app and loses the syllabus.
2. **The allowance** stops being a `facts--record` definition list, which drew a hairline
   above and below its row and put two lines across the inside of the new card. It is now a
   label, a tabular digit and five pips. Blocks rather than a percentage bar, because the
   quantity is five discrete things.
3. **The limits are stated above the picker**, in two lines, because there are two ceilings
   doing two different jobs and one strip naming a single megabyte figure would be read as
   covering both. The video line is gated behind `config.photos.video.enabled`, which ships
   **false**.
4. **The picker becomes a drop zone** with the button inside it, and everything funnels into
   `runBatch()`, the one entry point the picker already used.
5. **The transcript becomes chips.** This is the block the owner called "the comments".
6. **A critique pass**, which found four defects rather than polish.

## Four defects the critique caught

**The removal control was still square.** `.mine__remove` sits under a `--r-md` thumbnail and
was `--r-sm` with a 1px outline: a hard rectangle bolted to a soft frame, which is precisely
the quality the owner named, surviving in the one part of the block the first five commits
had not touched. Now a pill on a recessed fill.

**A dead rule.** The pip carried `transform: scaleY(1)` under a no-preference query. An
identity transform animating nothing, beside a comment claiming motion.

**A comment that lied.** The reduced motion block listed `.uploader__zone` and
`.mine__remove` and did nothing for either, because both are declared later at equal
specificity and their own `transition-property` won. Narrowed to the pip, with the reason the
other two are correct as they stand written down.

**The zone made no sense at desktop.** A wide dashed box with the button in its corner and
nothing saying why it was dashed. Control centred, one line of hint copy added, hidden on a
coarse pointer.

## Two contrast defects, both introduced by this plan

Worth recording separately because neither was visible and both were found by measuring.

`--accent-lit` is documented as 4.9:1 **against `--bg`**, which is the surface it was chosen
for. Making `.uploader` a card in commit 1 moved every red string in the block onto
`--surface`, which is lighter. Nothing looked wrong.

- Rows tinted white 0.03, the obvious move, put the **refusal reason** at **4.29:1**. That is
  the one string here a guest has to read and act on. Rows are now **recessed** with black
  0.25, which takes them back under `--bg`, and it measures **4.77:1**. A well is also the
  more honest thing for a transcript to be.
- In-flight and refused chips as red text on a red tint measured **3.74:1**. Every alpha from
  0.14 down to 0 was measured and none reached 4.5, because any tint that makes the chip
  visible also lightens the ground under the red. They are now **filled** with `--accent`
  carrying `--ink` at **8.11:1**, which is exactly what `.btn--primary` already does.

Final record, measured by compositing every translucent layer down to an opaque colour:

| Element | Ratio | |
|---|---|---|
| chip, refused / in flight | 8.11 | PASS |
| chip, done | 6.54 | PASS |
| refusal reason | 4.77 | PASS |
| file name | 17.42 | PASS |
| row number | 7.44 | PASS |
| status chip | 6.17 | PASS |
| rules strip | 7.15 | PASS |
| allowance label | 7.15 | PASS |
| alert line | 4.59 | PASS |

**The alert line is the one to watch.** It was 4.9 on `--bg` and the card cost it 0.3. It
still passes and it was left otherwise unchanged.

## The reflow guarantee, nearly lost and kept

`.uploader__status` reserves 24px in every state so the button and the album below do not
step when a batch starts, under the thumb that started it. Making it a chip added 3px of
vertical padding and took the filled line to **25.5px**, so everything below moved 2px. That
is exactly the reflow the `min-height` exists to prevent, reintroduced by a cosmetic change.

Fixed with `line-height: 18px`: 18 plus 3 plus 3 is 24 exactly. **Verified at zero drift**,
empty to filled to empty.

## An important limit on what was verified

**No photograph was uploaded during this work.** Every queue state was reached either by a
file the client refuses locally, or by writing the row's `data-state` attribute by hand to
photograph the chip. So the CSS for `uploading`, `recording` and `done` is verified, and the
**live transition between those states was not re-exercised.** The code driving them was not
changed by this plan, only its appearance, but that is a statement about the diff rather than
an observation.

The enrolment used to reach the control was faked in `localStorage`, so nothing was written
to Supabase at any point.

## Deviations from the UI spec

- `.queue__state` **keeps its class name** rather than becoming `.queue__chip`. The name still
  describes what it holds and renaming would touch the builder and the language re-seat for
  nothing a guest can see.
- The spec asked for chips in `rgba(232,63,72,0.14)` with `--accent-lit` text. **Measured and
  rejected at 3.74:1**, replaced by the filled treatment above.
- The spec asked for rows tinted `rgba(255,255,255,0.03)`. **Measured and rejected at 4.29:1**
  for the refusal reason, replaced by a recessed well.
- One copy key was added that the spec did not anticipate: `photos.zone.hint`.

`04.1-UI-SPEC.md` has not been rewritten to match. These four are the differences.

## Still true, still open

- `config.photos.video.enabled` is **false**, so the strip says nothing about video and the
  validator still refuses one. Plan 2 flips it.
- `opensAt` is still `null` and uploads remain open to anyone with the URL. Unchanged by this
  plan and still tracked in `restore-opensat-before-invitations`.
- Asset version is at **`?v=9`** on both pages.
